# 🗳 ระบบเลือกตั้งอิเล็กทรอนิกส์หน้างาน (On-site E-Voting System)

ระบบลงคะแนนเสียงหน้างานด้วย Node.js เพียงตัวเดียว (Single-run) พร้อม:

- **e-KYC ด้วยบัตรประชาชนไทย** — อ่านเลขบัตร 13 หลัก + ชื่อ-นามสกุล ผ่านเครื่องอ่านบัตร USB (PC/SC)
- **ป้องกันการลงคะแนนซ้ำ** — ตรวจสอบเลขบัตรกับ `activity_logs` ก่อนปลดล็อกบัตรเลือกตั้ง
- **บันทึกกิจกรรมนักศึกษา** — เก็บรายชื่อผู้มาใช้สิทธิ์สำหรับประเมินกิจกรรม
- **นับคะแนนแบบนิรนาม** — คะแนนไม่ผูกกับตัวผู้ลงคะแนน (แยกตาราง + vote token ใช้ครั้งเดียว)
- **แดชบอร์ดผู้ดูแล** — ดูบันทึกกิจกรรมและผลคะแนนสด อัปเดตทุก 3 วินาที
- **จัดการผู้สมัคร (CRUD)** — เพิ่ม/แก้ไข/ลบผู้สมัคร พร้อมอัปโหลดรูปภาพและรายละเอียด
  ได้จากแดชบอร์ด หน้าคูหาจะอัปเดตรายชื่อให้ทันทีผ่าน Socket.io
- **UI สไตล์เรโทร Windows 95** — มุมฉาก ขอบดำหนา สีสดใส เหมาะกับตู้คีออสก์

## ความต้องการของระบบ

| รายการ | รายละเอียด |
|---|---|
| Node.js | เวอร์ชัน 18 ขึ้นไป |
| MySQL | เปิดใช้งานผ่าน XAMPP (ค่าเริ่มต้น: root ไม่มีรหัสผ่าน) |
| เครื่องอ่านบัตร | Smart Card Reader มาตรฐาน PC/SC (เช่น ACS ACR39) |

## วิธีติดตั้งและรัน

```bash
# 1) เปิด MySQL ใน XAMPP Control Panel ก่อน

# 2) ติดตั้ง dependencies
npm install

# 3) รันระบบ (ฐานข้อมูล/ตาราง/ข้อมูลเริ่มต้นถูกสร้างอัตโนมัติ)
npm start
```

จากนั้นเปิดใช้งาน:

- **คูหาลงคะแนน**: http://localhost:3000/
- **ผู้ดูแลระบบ**: http://localhost:3000/admin — ผู้ใช้ `admin` รหัสผ่าน `password123`

> ไม่ต้อง import `database.sql` เอง — `server.js` จะสร้างฐานข้อมูล `evoting_db`,
> ตารางทั้ง 3 และข้อมูลเริ่มต้น (ผู้สมัครเบอร์ 1, 2, 99 และบัญชี admin) ให้อัตโนมัติ
> (ไฟล์ SQL มีไว้เพื่ออ้างอิงหรือติดตั้งด้วยตนเอง)

## การตั้งค่า (Environment Variables — ไม่บังคับ)

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตเว็บเซิร์ฟเวอร์ |
| `DB_HOST` | `localhost` | โฮสต์ MySQL |
| `DB_USER` | `root` | ผู้ใช้ MySQL |
| `DB_PASS` | *(ว่าง)* | รหัสผ่าน MySQL |
| `DB_NAME` | `evoting_db` | ชื่อฐานข้อมูล |
| `DEMO_MODE` | *(ปิด)* | ตั้งเป็น `1` เพื่อทดสอบโดยไม่มีเครื่องอ่านบัตร |

## ทดสอบโดยไม่มีเครื่องอ่านบัตร (Demo Mode)

```bash
# Windows (PowerShell)
$env:DEMO_MODE = "1"; npm start
```

จากนั้นที่หน้าคูหา (http://localhost:3000/) กดปุ่ม **F2** เพื่อจำลองการเสียบบัตร
ด้วยเลขบัตรสุ่ม — ใช้ทดสอบ flow ทั้งหมดได้โดยไม่ต้องมีเครื่องอ่านบัตรจริง

> หมายเหตุ: `@pokusew/pcsclite` เป็น optional dependency — หากติดตั้งไม่สำเร็จ
> (เช่น ไม่มี build tools) ระบบยังรันได้ตามปกติ เพียงแต่อ่านบัตรจริงไม่ได้
> การคอมไพล์ต้องมี Visual Studio Build Tools พร้อม workload
> **"Desktop development with C++"** (รวม MSVC toolset และ Windows SDK)

## ติดตั้งด้วย Docker / Coolify (Deploy)

รองรับการรันทั้งระบบ (แอป + MySQL) ด้วย Docker Compose — เหมาะสำหรับทดสอบบนเครื่อง
หรือ deploy ขึ้นเซิร์ฟเวอร์ผ่าน **Coolify** โดยไม่ต้องติดตั้ง Node.js/MySQL เอง

ไฟล์ที่เกี่ยวข้อง: `Dockerfile`, `docker-compose.yml`, `.dockerignore`, `.env.example`

### ทดสอบบนเครื่อง (Local)

```bash
# 1) (ไม่บังคับ) คัดลอกไฟล์ตั้งค่า — ค่าเริ่มต้นใช้งานได้ทันที
cp .env.example .env

# 2) build + รันทั้ง stack (แอป + ฐานข้อมูล)
docker compose up --build
```

จากนั้นเปิด http://localhost:3000/ (คูหา) และ http://localhost:3000/admin
(`admin` / `password123`)

- ฐานข้อมูล/ตาราง/ข้อมูลเริ่มต้นถูกสร้างอัตโนมัติเมื่อแอปสตาร์ต
- ข้อมูล MySQL เก็บใน volume `db_data` และรูปผู้สมัครที่อัปโหลดเก็บใน volume
  `uploads` — คงอยู่แม้ rebuild container
- ปิดระบบด้วย `docker compose down` (ข้อมูลยังอยู่) หรือ
  `docker compose down -v` เพื่อลบ volume ทั้งหมด

### Deploy ด้วย Coolify

1. สร้าง Resource ใหม่ → ชี้ไปที่ Git repo นี้ → เลือก build pack แบบ
   **Docker Compose**
2. ตั้งค่า Environment Variables ในหน้า Coolify อย่างน้อย:
   **`DB_PASS`** และ **`SESSION_SECRET`** (สตริงสุ่มยาว ๆ) — คงค่า `DEMO_MODE=1`
3. Coolify จะจัดการ public domain + HTTPS ให้อัตโนมัติ
   (สามารถลบ `ports:` ใน `docker-compose.yml` ออกได้หากใช้ proxy ของ Coolify)

> **หมายเหตุ:** ใน container จะ **ไม่มี** ไลบรารีอ่านบัตร (`@pokusew/pcsclite`)
> เพราะเข้าถึงเครื่องอ่านบัตร USB ผ่าน Docker ไม่ได้ จึงต้องใช้ `DEMO_MODE=1`
> (กด F2 จำลองบัตร) หากต้องอ่านบัตรจริง ให้ติดตั้งบนเครื่องจริงด้วย `install.sh` แทน
>
> **โปรดักชัน:** เปลี่ยนรหัสผ่าน `admin` และตั้ง `SESSION_SECRET` ที่สุ่มยาว
> ก่อนใช้งานจริง (session ปัจจุบันเก็บใน memory — เหมาะกับ container เดียว)

## จัดการผู้สมัคร (Manage Candidates)

ที่แดชบอร์ดผู้ดูแล ส่วน **"จัดการผู้สมัคร"** สามารถ:

- **เพิ่มผู้สมัคร** — กำหนดหมายเลข (0-999), ชื่อ, รายละเอียด (นโยบาย/สังกัด)
  และอัปโหลดรูปภาพ (PNG/JPG/GIF/WebP/SVG สูงสุด 3 MB)
- **แก้ไข** — เปลี่ยนชื่อ/รายละเอียด/รูปได้ทุกเมื่อ (หมายเลขเปลี่ยนไม่ได้ —
  ให้ลบแล้วเพิ่มใหม่แทน) รูปเก่าที่อัปโหลดไว้จะถูกลบให้อัตโนมัติ
- **ลบ** — กดปุ่มลบ 2 ครั้งเพื่อยืนยัน (กันกดพลาด)

รูปที่อัปโหลดถูกเก็บใน `public/img/uploads/` และหน้าคูหาจะโหลดรายชื่อ
ผู้สมัครใหม่ทันทีที่มีการแก้ไข (ผ่านเหตุการณ์ `candidates-updated` ของ Socket.io)

## ขั้นตอนการทำงานของคูหา (State Machine)

1. **หน้าต้อนรับ** — "กรุณาเสียบบัตรประชาชนเพื่อลงคะแนนเสียง"
2. **ตรวจสอบตัวตน** — อ่านเลขบัตร + ชื่อจากบัตร
   - เคยลงคะแนนแล้ว → เตือน **"คุณได้ลงคะแนนไปแล้ว!"** 4 วินาที แล้วรีเซ็ต
   - ยังไม่เคย → บันทึกเข้า `activity_logs` ทันที แล้วปลดล็อกบัตรเลือกตั้ง
3. **บัตรเลือกตั้ง** — กดปุ่มลงคะแนนใต้ผู้สมัคร (ส่งแบบนิรนามด้วย vote token
   ใช้ได้ครั้งเดียว) → หน้า **"ขอบคุณ"** 3 วินาที → กลับหน้าต้อนรับ

## หมายเหตุด้านความปลอดภัย

- รหัสผ่าน admin ถูกเก็บเป็น **bcrypt hash** (สร้างอัตโนมัติตอนรันครั้งแรก)
- การลงคะแนนต้องมี **vote token** ที่ออกให้หลังเสียบบัตรเท่านั้น และใช้ได้ครั้งเดียว
  (หมดอายุใน 5 นาที) — ป้องกันการยิง API ลงคะแนนโดยตรง
- ตารางคะแนน (`vote_candidates`) เก็บเฉพาะยอดรวม **ไม่มีข้อมูลว่าใครเลือกใคร**
- ควรเปลี่ยนรหัสผ่าน admin เริ่มต้นก่อนใช้งานจริง
