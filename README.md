# 🗳 ระบบเลือกตั้งอิเล็กทรอนิกส์หน้างาน (On-site E-Voting System)

ระบบลงคะแนนเสียงหน้างานด้วย Node.js เพียงตัวเดียว (Single-run) พร้อม:

- **e-KYC ด้วยบัตรประชาชนไทย** — อ่านเลขบัตร 13 หลัก + ชื่อ-นามสกุล ผ่านเครื่องอ่านบัตร USB (PC/SC)
- **ป้องกันการลงคะแนนซ้ำ** — ตรวจสอบเลขบัตรกับ `activity_logs` ก่อนปลดล็อกบัตรเลือกตั้ง
- **นับว่าใช้สิทธิ์เมื่อลงคะแนนสำเร็จเท่านั้น** — การเสียบบัตรไม่ถือว่าใช้สิทธิ์
  (เครื่องอ่านผิดพลาด / เดินออกก่อนลงคะแนน → เสียบบัตรใหม่ได้)
- **หลายกิจกรรมเลือกตั้งในวันเดียว** — เสียบบัตรครั้งเดียว ลงคะแนนทุกกิจกรรมที่มีสิทธิ์ทีละใบ
- **บัญชีรายชื่อผู้มีสิทธิ์เลือกตั้ง** — import จาก CSV/Excel, พิมพ์ประกาศรายชื่อ,
  พิมพ์บัญชีลงลายมือชื่อ, ติดตามว่าใครมาใช้สิทธิ์แล้ว
- **รายงานผลการเลือกตั้ง** — พิมพ์/บันทึก PDF พร้อมช่องลงนามกรรมการ และส่งออก CSV
- **เจ้าหน้าที่กรอกเลขบัตรแทน** — เมื่อชิปบัตรอ่านไม่ได้ ใช้ PIN ของเจ้าหน้าที่ (บันทึกว่าใครกรอกให้ใคร)
- **ผู้ใช้หลายบัญชี 2 บทบาท** — ผู้ดูแลระบบ / เจ้าหน้าที่ (อ่านอย่างเดียว) + เปลี่ยนรหัสผ่าน + กันเดารหัส
- **บันทึกการใช้งานระบบ (Audit Log)** — ทุกการกระทำของผู้ดูแล/เจ้าหน้าที่ลงฐานข้อมูล ลบไม่ได้
- **ซ่อนผลคะแนนจนกว่าจะปิดลงคะแนน** และ **ตั้งเวลาเปิด-ปิดลงคะแนนอัตโนมัติ**
- **สำรอง / กู้คืนข้อมูล** — อัตโนมัติตามรอบเวลาและทุกครั้งที่ปิดลงคะแนน, session เก็บใน MySQL
- **บันทึกกิจกรรมนักศึกษา** — เก็บรายชื่อผู้มาใช้สิทธิ์สำหรับประเมินกิจกรรม
- **นับคะแนนแบบนิรนาม** — คะแนนไม่ผูกกับตัวผู้ลงคะแนน (แยกตาราง + vote token ใช้ครั้งเดียว)
- **แดชบอร์ดผู้ดูแล** — ดูบันทึกกิจกรรมและผลคะแนนสด อัปเดตทุก 3 วินาที
- **จัดการผู้สมัคร (CRUD)** — เพิ่ม/แก้ไข/ลบผู้สมัคร (แยกตามกิจกรรม) พร้อมอัปโหลดรูปภาพและรายละเอียด
- **UI สไตล์เรโทร Windows 95** — มุมฉาก ขอบดำหนา สีสดใส เหมาะกับตู้คีออสก์

## ความต้องการของระบบ

| รายการ | รายละเอียด |
|---|---|
| Node.js | เวอร์ชัน 18 ขึ้นไป |
| MySQL | เปิดใช้งานผ่าน XAMPP (ค่าเริ่มต้น: root ไม่มีรหัสผ่าน) |
| เครื่องอ่านบัตร | Smart Card Reader มาตรฐาน PC/SC (เช่น ACS ACR39) |

## วิธีติดตั้งและรัน

```bash
# 1) เปิด MySQL ใน XAMPP Control Panel ก่อน

# 2) ติดตั้ง dependencies
npm install

# 3) รันระบบ (ฐานข้อมูล/ตาราง/ข้อมูลเริ่มต้นถูกสร้างอัตโนมัติ)
npm start
```

จากนั้นเปิดใช้งาน:

- **คูหาลงคะแนน**: http://localhost:3000/
- **ผู้ดูแลระบบ**: http://localhost:3000/admin — ผู้ใช้ `admin` รหัสผ่าน `password123`

> ไม่ต้อง import `database.sql` เอง — `server.js` จะสร้างฐานข้อมูล `evoting_db`,
> ตารางทั้งหมดและข้อมูลเริ่มต้น (ผู้สมัครเบอร์ 1, 2, 99 และบัญชี admin) ให้อัตโนมัติ
> (ไฟล์ SQL มีไว้เพื่ออ้างอิงหรือติดตั้งด้วยตนเอง)

## การตั้งค่า (Environment Variables — ไม่บังคับ)

| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตเว็บเซิร์ฟเวอร์ |
| `DB_HOST` | `localhost` | โฮสต์ MySQL |
| `DB_USER` | `root` | ผู้ใช้ MySQL |
| `DB_PASS` | *(ว่าง)* | รหัสผ่าน MySQL |
| `DB_NAME` | `evoting_db` | ชื่อฐานข้อมูล |
| `DEMO_MODE` | *(ปิด)* | ตั้งเป็น `1` เพื่อทดสอบโดยไม่มีเครื่องอ่านบัตร |
| `TZ` | `Asia/Bangkok` | เขตเวลาของเวลาที่แสดงผลและบันทึกทั้งหมด (UTC+7) |
| `DB_TIMEZONE` | *(คำนวณจาก `TZ`)* | เขตเวลาฝั่ง MySQL — ต้องเป็น offset เช่น `+07:00` |
| `SESSION_SECRET` | *(สุ่มแล้วเก็บในฐานข้อมูล)* | คีย์เซ็น cookie — ควรตั้งเป็นสตริงสุ่มยาว ๆ |
| `BACKUP_INTERVAL_HOURS` | `6` | สำรองข้อมูลอัตโนมัติทุกกี่ชั่วโมง (`0` = เฉพาะตอนปิดลงคะแนน) |
| `BACKUP_KEEP` | `30` | เก็บไฟล์สำรองล่าสุดกี่ไฟล์ |
| `BACKUP_DIR` | `./backups` | โฟลเดอร์เก็บไฟล์สำรอง (ใน Docker = volume `backups`) |
| `TRUST_PROXY` | `1` | อยู่หลัง reverse proxy (Coolify) — ได้ IP จริงใน audit log และ cookie แบบ secure |

> เวลาที่บันทึกการใช้สิทธิ์ (`voted_at`) ใช้เขตเวลา **Asia/Bangkok (UTC+7)**
> ทั้งฝั่งเซิร์ฟเวอร์และฐานข้อมูล แม้จะรันบน Cloud/Docker ที่ตั้งเป็น UTC ก็ตาม
> ตรวจสอบได้ที่หน้า "ตรวจสอบระบบ" ในแดชบอร์ดผู้ดูแล (หัวข้อ *เขตเวลา*)

## ทดสอบโดยไม่มีเครื่องอ่านบัตร (Demo Mode)

```bash
# Windows (PowerShell)
$env:DEMO_MODE = "1"; npm start
```

จากนั้นที่หน้าคูหา (http://localhost:3000/) กดปุ่ม **F2** เพื่อจำลองการเสียบบัตร
— ใช้ทดสอบ flow ทั้งหมดได้โดยไม่ต้องมีเครื่องอ่านบัตรจริง

- **F2** = สุ่มผู้มีสิทธิ์ที่ยังไม่ได้ลงคะแนนจากบัญชีรายชื่อของกิจกรรมที่เปิดอยู่
  (ถ้าไม่มีบัญชีรายชื่อ จะใช้เลขบัตรสุ่ม)
- **F3** = เลขบัตรสุ่มที่ไม่อยู่ในบัญชีรายชื่อ (ทดสอบหน้าจอ "ไม่พบรายชื่อ")

> หมายเหตุ: `@pokusew/pcsclite` เป็น optional dependency — หากติดตั้งไม่สำเร็จ
> (เช่น ไม่มี build tools) ระบบยังรันได้ตามปกติ เพียงแต่อ่านบัตรจริงไม่ได้
> การคอมไพล์ต้องมี Visual Studio Build Tools พร้อม workload
> **"Desktop development with C++"** (รวม MSVC toolset และ Windows SDK)

## ติดตั้งด้วย Docker / Coolify (Deploy)

รองรับการรันทั้งระบบ (แอป + MySQL) ด้วย Docker Compose — เหมาะสำหรับทดสอบบนเครื่อง
หรือ deploy ขึ้นเซิร์ฟเวอร์ผ่าน **Coolify** โดยไม่ต้องติดตั้ง Node.js/MySQL เอง

ไฟล์ที่เกี่ยวข้อง: `Dockerfile`, `docker-compose.yml`, `.dockerignore`, `.env.example`

### ทดสอบบนเครื่อง (Local)

```bash
# 1) (ไม่บังคับ) คัดลอกไฟล์ตั้งค่า — ค่าเริ่มต้นใช้งานได้ทันที
cp .env.example .env

# 2) build + รันทั้ง stack (แอป + ฐานข้อมูล)
docker compose up --build
```

จากนั้นเปิด http://localhost:3000/ (คูหา) และ http://localhost:3000/admin
(`admin` / `password123`)

- ฐานข้อมูล/ตาราง/ข้อมูลเริ่มต้นถูกสร้างอัตโนมัติเมื่อแอปสตาร์ต
- ข้อมูล MySQL เก็บใน volume `db_data` และรูปผู้สมัครที่อัปโหลดเก็บใน volume
  `uploads` — คงอยู่แม้ rebuild container
- ปิดระบบด้วย `docker compose down` (ข้อมูลยังอยู่) หรือ
  `docker compose down -v` เพื่อลบ volume ทั้งหมด

### Deploy ด้วย Coolify

1. สร้าง Resource ใหม่ → ชี้ไปที่ Git repo นี้ → เลือก build pack แบบ
   **Docker Compose**
2. ตั้งค่า Environment Variables ในหน้า Coolify อย่างน้อย:
   **`DB_PASS`** และ **`SESSION_SECRET`** (สตริงสุ่มยาว ๆ) — คงค่า `DEMO_MODE=1`
   (ไม่บังคับ: `BACKUP_INTERVAL_HOURS`, `BACKUP_KEEP` — ค่าเริ่มต้น 6 ชั่วโมง / 30 ไฟล์)
3. Coolify จะจัดการ public domain + HTTPS ให้อัตโนมัติ
   (สามารถลบ `ports:` ใน `docker-compose.yml` ออกได้หากใช้ proxy ของ Coolify)

> **หมายเหตุ:** ใน container จะ **ไม่มี** ไลบรารีอ่านบัตร (`@pokusew/pcsclite`)
> เพราะเข้าถึงเครื่องอ่านบัตร USB ผ่าน Docker ไม่ได้ จึงต้องใช้ `DEMO_MODE=1`
> (กด F2 จำลองบัตร) หากต้องอ่านบัตรจริง ให้ติดตั้งบนเครื่องจริงด้วย `install.sh` แทน
>
> **โปรดักชัน:** เปลี่ยนรหัสผ่าน `admin` และตั้ง `SESSION_SECRET` ที่สุ่มยาว
> ก่อนใช้งานจริง (session เก็บใน MySQL — ไม่หลุดเมื่อ redeploy)

## กิจกรรมเลือกตั้ง (Elections)

สร้างได้หลายกิจกรรม (เช่น เลือกนายกองค์การฯ + เลือกประธานชมรม ในวันเดียวกัน)
แต่ละกิจกรรมมีผู้สมัคร บัญชีรายชื่อ และบันทึกผู้มาใช้สิทธิ์เป็นของตัวเอง

| สถานะ | ความหมาย |
|---|---|
| เตรียมการ | เพิ่มผู้สมัคร / import รายชื่อ — คูหายังไม่แสดงบัตร |
| เปิดลงคะแนน | คูหาแสดงบัตรเลือกตั้งของกิจกรรมนี้ |
| ปิดลงคะแนนแล้ว | ลงคะแนนไม่ได้ พิมพ์รายงานผลอย่างเป็นทางการได้ |

- เปิดได้หลายกิจกรรมพร้อมกัน — เมื่อเสียบบัตร คูหาจะแสดงบัตรเลือกตั้งของ
  **ทุกกิจกรรมที่เปิดอยู่ซึ่งผู้นั้นมีสิทธิ์และยังไม่ได้ลงคะแนน** ให้ลงทีละใบ
- ตัวเลือก **"เฉพาะผู้ที่มีชื่อในบัญชีรายชื่อ"** — ปิดไว้ = ทุกคนที่มีบัตรประชาชนลงคะแนนได้
- กิจกรรมใหม่มีช่อง "ไม่ประสงค์ลงคะแนน" (หมายเลข 99) ให้อัตโนมัติ
- ฐานข้อมูลรุ่นเก่าจะถูกอัปเกรดอัตโนมัติ: ผู้สมัครและบันทึกเดิมย้ายไปอยู่ในกิจกรรม
  "การเลือกตั้ง (ข้อมูลเดิม)" ซึ่งเปิดลงคะแนนไว้และไม่บังคับบัญชีรายชื่อ (ทำงานเหมือนเดิม)

## บัญชีรายชื่อผู้มีสิทธิ์เลือกตั้ง (Eligible Voters)

**Import** — วางข้อมูลที่คัดลอกจาก Excel (Ctrl+C) หรือเลือกไฟล์ CSV
(รองรับทั้ง UTF-8 และ CSV ภาษาไทยแบบเก่า TIS-620) กด "ตรวจสอบข้อมูล" เพื่อดูตัวอย่าง
และแถวที่ผิดก่อน แล้วจึงกด "ยืนยัน Import"

```
เลขประจำตัวประชาชน,คำนำหน้า,ชื่อ,นามสกุล,ชั้น
1101700203450,นาย,สมชาย,ใจดี,ปวช.1/1
```

- มีแถวหัวตารางหรือไม่ก็ได้ / คำนำหน้าแยกคอลัมน์หรือติดกับชื่อก็ได้ /
  ชื่อ-นามสกุลอยู่ช่องเดียวกันก็ได้
- ตรวจเลขบัตรด้วยหลักตรวจสอบ (check digit) — เลขที่พิมพ์ผิดจะถูกแจ้งและข้าม
- เลขบัตรซ้ำกับที่มีอยู่ = อัปเดตชื่อ/กลุ่ม (ไม่เพิ่มซ้ำ)
- เพิ่มทีละคน / ลบรายคน / คัดลอกบัญชีจากกิจกรรมอื่นได้

**พิมพ์** (A4 หรือบันทึกเป็น PDF จากหน้าต่างพิมพ์ของเบราว์เซอร์):

- **ประกาศรายชื่อผู้มีสิทธิ์** — สำหรับติดประกาศ ค่าเริ่มต้น **ปิดเลขบัตรบางส่วน**
  (`x-xxxx-xxxxx-12-3`) เพื่อคุ้มครองข้อมูลส่วนบุคคล (PDPA) แยกตามกลุ่ม/ชั้นได้
- **บัญชีลงลายมือชื่อ** — สำหรับเจ้าหน้าที่ แสดงสถานะ/เวลามาใช้สิทธิ์จากระบบ + ช่องลงชื่อ

สถานะ "มาใช้สิทธิ์แล้ว" ในบัญชีรายชื่อมาจาก `activity_logs` โดยตรง (แหล่งข้อมูลเดียว)

## รายงานผลการเลือกตั้ง (Reports)

ปุ่ม **"🖨 รายงานผล"** บนแถบกิจกรรม — พิมพ์ได้ทีละกิจกรรมหรือ "ทุกกิจกรรมในวันเดียวกัน":

- ผู้มีสิทธิ์ / ผู้มาใช้สิทธิ์ / ร้อยละ / ผู้ไม่มาใช้สิทธิ์ / บัตรไม่ประสงค์ลงคะแนน
- ผลคะแนนเรียงอันดับ พร้อมผู้ได้คะแนนสูงสุด (แจ้งกรณีคะแนนเท่ากัน)
- ผู้มาใช้สิทธิ์แยกตามกลุ่ม/ชั้น และรายชั่วโมง
- **ตรวจสอบความถูกต้อง**: จำนวนบัตรที่นับได้ต้องเท่ากับจำนวนผู้มาใช้สิทธิ์
- ช่องลงนามคณะกรรมการ 3 ท่าน — ถ้ายังเปิดลงคะแนนอยู่ จะพิมพ์ว่า "ผลอย่างไม่เป็นทางการ"

ส่งออก CSV (เปิดด้วย Excel ได้ทันที): บัญชีรายชื่อ+สถานะ, ผู้มาใช้สิทธิ์, ผลคะแนน

## เจ้าหน้าที่กรอกเลขบัตรแทน (เมื่ออ่านบัตรไม่ได้)

1. เจ้าหน้าที่ตั้ง **PIN 6 หลัก** ของตัวเองที่แดชบอร์ด → "👤 บัญชีของฉัน"
   (PIN ต้องไม่ซ้ำกับผู้อื่น และห้ามเป็นเลขเรียง/เลขซ้ำ)
2. ที่หน้าคูหา กดปุ่ม **"🔑 เจ้าหน้าที่"** มุมล่าง (หรือกด **F9**) → ใส่ PIN + เลขบัตรประชาชน 13 หลัก
   (มีแป้นตัวเลขบนจอสำหรับจอสัมผัส) — ตรวจบัตรของผู้มาใช้สิทธิ์ด้วยสายตาก่อนทุกครั้ง
3. ระบบตรวจสิทธิ์เหมือนเสียบบัตร (ใช้ชื่อจากบัญชีรายชื่อถ้ามี) แล้วแสดงบัตรเลือกตั้ง
   พร้อมป้าย "ยืนยันตัวตนโดยเจ้าหน้าที่"

- ทุกครั้งถูกบันทึกใน audit log (เลขบัตรปิดบางส่วน) และบันทึกผู้มาใช้สิทธิ์แสดงว่า
  "เจ้าหน้าที่กรอก (ชื่อผู้ใช้)" — รายงานผลแสดงจำนวนผู้ที่ยืนยันตัวตนด้วยวิธีนี้
- ใส่ PIN ผิด 5 ครั้ง → เครื่องนั้นถูกล็อก 5 นาที

## บัญชีผู้ใช้และความปลอดภัย

| บทบาท | ทำได้ |
|---|---|
| **ผู้ดูแลระบบ** | ทุกอย่าง: กิจกรรม ผู้สมัคร บัญชีรายชื่อ ล้างข้อมูล ผู้ใช้ สำรอง/กู้คืน audit log |
| **เจ้าหน้าที่** | ดูกิจกรรม/ผลที่เปิดเผยแล้ว/บัญชีรายชื่อ/ผู้มาใช้สิทธิ์ พิมพ์เอกสาร และกรอกเลขบัตรแทนที่คูหา |

- บัญชีแรก `admin` / `password123` — ระบบขึ้นแถบแดงเตือนจนกว่าจะเปลี่ยนรหัสผ่าน
  (และหน้าตรวจสอบระบบแสดง "ไม่ผ่าน")
- รหัสผ่านอย่างน้อย 8 ตัว / ใส่รหัสผิด 5 ครั้ง → ชื่อผู้ใช้นั้นถูกล็อก 5 นาที (ต่อ IP)
- เปลี่ยน/รีเซ็ตรหัสผ่าน หรือลบผู้ใช้ → session อื่นของผู้ใช้นั้นถูกออกจากระบบทันที
- session เก็บใน MySQL — ไม่หลุดจากระบบเมื่อ restart / redeploy

**บันทึกการใช้งานระบบ (Audit Log)** — เข้าระบบ (สำเร็จ/ล้มเหลว), เปิด-ปิดลงคะแนน,
แก้ไขกิจกรรม/ผู้สมัคร, import รายชื่อ, ดาวน์โหลดข้อมูลส่วนบุคคล (CSV), ล้างข้อมูล,
กรอกเลขบัตรแทน, สำรอง/กู้คืน ฯลฯ พร้อมเวลาและ IP — ไม่มีหน้าลบ และ**ไม่มีข้อมูลว่าใครเลือกใคร**

## ซ่อนผลคะแนน / ตั้งเวลาเปิด-ปิด

- **ซ่อนผลคะแนนจนกว่าจะปิดลงคะแนน** (ค่าเริ่มต้นของกิจกรรมใหม่) — ระหว่างเปิด ทุกคน
  (รวมผู้ดูแล) เห็นเฉพาะจำนวนผู้มาใช้สิทธิ์และจำนวนบัตรรวม ไม่เห็นคะแนนรายผู้สมัคร
  (API / รายงาน / CSV ซ่อนทั้งหมด) — ยกเลิกการซ่อนระหว่างเปิดได้แต่ถูกบันทึกใน audit log
- **เปิด/ปิดลงคะแนนอัตโนมัติ** — ตั้งวันเวลา (เวลาไทย) ในฟอร์มกิจกรรม ระบบตรวจทุก 15 วินาที
  - ถ้าถึงเวลาเปิดแต่ยังเปิดไม่ได้ (ไม่มีผู้สมัคร/ไม่มีบัญชีรายชื่อ) → ยกเลิกเวลาเปิดและบันทึกใน audit log
  - ปิดลงคะแนนเองก่อนเวลา → เวลาที่ตั้งไว้ถูกยกเลิก (ระบบไม่เปิดซ้ำเอง)

## สำรอง / กู้คืนข้อมูล

- สำรองอัตโนมัติทุก `BACKUP_INTERVAL_HOURS` ชั่วโมง + **ทุกครั้งที่ปิดลงคะแนน**
  + ก่อนลบกิจกรรม / ล้างข้อมูล / กู้คืน (เก็บ `BACKUP_KEEP` ไฟล์ล่าสุด)
- ไฟล์ `.sql.gz` ถูกสร้างโดยแอปเอง (ไม่ต้องมี mysqldump) แบบ consistent snapshot
  — สำรองระหว่างมีคนลงคะแนนได้ ข้อมูลทุกตารางตรงกัน
- แดชบอร์ด → "💾 สำรอง / กู้คืนข้อมูล": สำรองตอนนี้, ดาวน์โหลด, อัปโหลดไฟล์ที่เคยดาวน์โหลด,
  กู้คืน (ต้องปิดลงคะแนนทุกกิจกรรม + พิมพ์ `RESTORE` — ระบบสำรองข้อมูลปัจจุบันไว้ก่อนเสมอ)
- **ควรดาวน์โหลดไฟล์สำรองเก็บนอกเซิร์ฟเวอร์** (เช่น หลังปิดลงคะแนน) — ถ้าเซิร์ฟเวอร์เสีย
  volume ก็อาจหายไปด้วย
- กู้คืนด้วยคำสั่งได้เช่นกัน: `gunzip -c ไฟล์.sql.gz | mysql -u root -p evoting_db`

## จัดการผู้สมัคร (Manage Candidates)

ที่แดชบอร์ดผู้ดูแล ส่วน **"จัดการผู้สมัคร"** (ของกิจกรรมที่เลือกอยู่บนแถบสีเหลือง) สามารถ:

- **เพิ่มผู้สมัคร** — กำหนดหมายเลข (0-999), ชื่อ, รายละเอียด (นโยบาย/สังกัด)
  และอัปโหลดรูปภาพ (PNG/JPG/GIF/WebP/SVG สูงสุด 3 MB)
- **แก้ไข** — เปลี่ยนชื่อ/รายละเอียด/รูปได้ทุกเมื่อ (หมายเลขเปลี่ยนไม่ได้ —
  ให้ลบแล้วเพิ่มใหม่แทน) รูปเก่าที่อัปโหลดไว้จะถูกลบให้อัตโนมัติ
- **ลบ** — กดปุ่มลบ 2 ครั้งเพื่อยืนยัน (กันกดพลาด) — ผู้สมัครที่มีคะแนนแล้วลบไม่ได้

รูปที่อัปโหลดถูกเก็บใน `public/img/uploads/` — รายชื่อผู้สมัครถูกส่งไปพร้อมบัตรเลือกตั้ง
ทุกครั้งที่เสียบบัตร จึงเป็นข้อมูลล่าสุดเสมอ

## ขั้นตอนการทำงานของคูหา (State Machine)

1. **หน้าต้อนรับ** — "กรุณาเสียบบัตรประชาชนเพื่อลงคะแนนเสียง" + รายชื่อกิจกรรมที่เปิดอยู่
2. **ตรวจสอบตัวตน** — อ่านเลขบัตร + ชื่อจากบัตร แล้วหากิจกรรมที่เปิดอยู่ซึ่งผู้นั้น
   มีสิทธิ์ (อยู่ในบัญชีรายชื่อ หรือกิจกรรมไม่บังคับบัญชี) และยังไม่ได้ลงคะแนน
   - ไม่มีชื่อในบัญชีรายชื่อ → **"ไม่พบรายชื่อของท่าน"** 5 วินาที
   - ลงครบทุกกิจกรรมแล้ว → **"คุณได้ลงคะแนนไปแล้ว!"** 4 วินาที
   - ยังมีกิจกรรมที่ต้องลง → ปลดล็อกบัตรเลือกตั้ง (**ยังไม่บันทึกว่าใช้สิทธิ์**)
3. **บัตรเลือกตั้ง** — ทีละกิจกรรม ("บัตรเลือกตั้งใบที่ 1 จาก 2") กดเลือก → หน้าต่าง
   **ยืนยัน** → บันทึกผู้มาใช้สิทธิ์ + เพิ่มคะแนนใน transaction เดียวกัน
   → ใบถัดไป / หน้า **"ขอบคุณ"** 3 วินาที → กลับหน้าต้อนรับ
   - ไม่ลงคะแนนภายใน 120 วินาที → กลับหน้าแรก (ยังไม่ใช้สิทธิ์ เสียบบัตรใหม่ได้)
   - เสียบบัตรเดียวกันที่ 2 เครื่องพร้อมกัน → นับได้ครั้งเดียว อีกเครื่องแจ้งว่าลงแล้ว

## หมายเหตุด้านความปลอดภัย

- รหัสผ่าน admin ถูกเก็บเป็น **bcrypt hash** (สร้างอัตโนมัติตอนรันครั้งแรก)
- การลงคะแนนต้องมี **vote token** ที่ออกให้หลังเสียบบัตรเท่านั้น และใช้ได้ครั้งเดียวต่อกิจกรรม
  (หมดอายุใน 5 นาที) — ป้องกันการยิง API ลงคะแนนโดยตรง
- token เก็บในหน่วยความจำเซิร์ฟเวอร์เท่านั้น — ฐานข้อมูลบันทึกแค่ "ใครมาใช้สิทธิ์"
  กับ "ยอดรวมคะแนน" แยกกัน ไม่มีข้อมูลว่าใครเลือกใคร
- ล้างผลการลงคะแนนได้เฉพาะกิจกรรมที่ปิดแล้ว และล้างบันทึกผู้มาใช้สิทธิ์พร้อมคะแนนเสมอ
  (ป้องกันจำนวนบัตรกับผู้มาใช้สิทธิ์ไม่ตรงกัน)
- ตารางคะแนน (`vote_candidates`) เก็บเฉพาะยอดรวม **ไม่มีข้อมูลว่าใครเลือกใคร**
- ควรเปลี่ยนรหัสผ่าน admin เริ่มต้นก่อนใช้งานจริง
